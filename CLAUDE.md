# Nano Cortex Editor

Desktop editor for the Neural DSP Nano Cortex (Electron edition). Unofficial. Repo: <https://github.com/AJs-Creations/nano-cortex-editor> (MIT, © AJs Creations); builds are published as GitHub Releases (`.github/workflows/release.yml`, on `v*` tags, notes from `CHANGELOG.md`) for macOS, Windows and Linux. Never ship anything that could be mistaken for a Neural DSP product: no Neural DSP logos, no screenshots of the Cortex Cloud website, and keep the trademark note in the README and `docs/MANUAL.md`.

User docs: `README.md`, `docs/MANUAL.md` (screenshots from `npm run docs:screenshots`, demo mode). Developer docs index: `docs/README.md`. `CONTRIBUTING.md` has the branch and privacy rules.

**Start with `docs/HANDOFF.md`.** It has the ordered plan. Step 0 is a stack decision for Anup; `docs/INVESTIGATION.md` holds the evidence (Cortex Control teardown, USB findings, community protocol survey).

## Current state

- The app runs as an Electron app with two tabs: the pro editor (`pro/`) and the Cortex Cloud website (their real login, persistent session).
- This repo is the Electron product for good (and the shareable one). The native Mac edition is <https://github.com/AJs-Creations/nano-cortex-editor-mac> (local clone `../nano-cortex-editor-mac`); the two READMEs link each other.
- **No recordings in git, ever** (not even in history): session recordings, `.pklg`/HCI traces and capture bundles stay local (`test/fixtures/sessions/` and those types are git-ignored). Tests inline the specific frames they need with identifying values replaced.
- Hardware-verified on a Nano Cortex (firmware 2.2.1) on 2026-10-08, including Cortex Cloud → pedal capture transfer. `npm run test:ux` passes 866/866 on macOS with demo data (CI, `.github/workflows/ci.yml`, on PRs to `staging`/`main`: a required smoke job and the UX test, also required; the test waits on conditions, not fixed sleeps, so it holds on GitHub's slow macOS runners). Windows and Linux are untested with a pedal; `ux-test-linux` (not required) runs the same test on ubuntu-latest under Xvfb.
- Inside VS Code's terminal `ELECTRON_RUN_AS_NODE=1` is set, which makes `electron` behave like `node`. The npm scripts clear it; if you run `electron` by hand, prefix `env -u ELECTRON_RUN_AS_NODE`.

## Commands

```bash
npm install
npm start               # regenerates pro/core.js, then launches
npm run test:ux         # input-driven UX test on demo data; screenshots → test-output/
npm run build:core      # regenerate pro/core.js from editor/index.html
npm run build:preview   # single-file browser preview → dist-preview/
npm run dist            # .dmg/.zip (arm64 + x64), ad-hoc signed locally (mac.identity "-"); must run on macOS
npm run dist:linux      # AppImage + deb (x64 + arm64); run on Linux (CI: release.yml)
npm run build:icon      # assets/icon.svg → build/icon.icns, build/icon.png, pro/assets/icon-*.png (macOS)
npm run docs:screenshots # regenerate docs/images/ in demo mode (needs Python + Pillow)
```

## Architecture

- `editor/index.html`: the upstream community editor ([DrD85/nano-cortex-editor](https://github.com/DrD85/nano-cortex-editor), MIT; commit in `editor/README.md`), **verbatim**. Don't edit it. It's the protocol reference and the "Classic Editor" fallback (View menu).
- `scripts/build-core.js`: parses the upstream script with acorn and keeps only the declarations reachable from the functions the pro UI calls (`ENTRY`). Upstream UI functions the pro UI replaces (`HOOKS`: `render`, `log`, `toast`, `showSaveResult`, `chooseSlot`, …) become empty stubs. `$()` is patched to return a dummy element for ids the pro page lacks. It fails loudly if upstream renamed anything in `ENTRY`.
- `pro/core.js`: **generated, never hand-edit.** It defines the global `state`, `MSG` (message types), every device write (`setFXParam`, `setAmpKnob`, `savePreset`, `selectPreset`, `renamePresetTo`, `loadLibraryCapture`, …) and the notification parsers (`onC305`, `handleTypedMessage`).
- `pro/links.js`: the one place for outside links (repo, manual, troubleshooting anchor, issues, native edition, Buy Me a Coffee) and the version shown in Settings → About (keep it equal to `package.json`; the UX test checks). Loaded by the page and required by `src/main.js` (Help menu, About panel). Links always open in the default browser (`window.nanoShell.openExternal` → `shell.openExternal`, allowlisted hosts); support stays quiet: no prompts, counters or accent.
- `pro/capture-text.js`: capture descriptions. `NanoText.storedDescription` (what is sent: empty, blank and "null" mean none), `captureDescription` (what is shown and searched: the same, and a description that is only a Cortex Cloud product ID is none too) and `captureCloudId` (that ID in lowercase when the whole trimmed description is one UUID, else null). Info takes the description from the type-18 reply's field 8, else from its capture record's field 5 (as native). Capture **Info…** shows **Open in Cortex Cloud** (`cap-cloud-link`, ghost small button, tooltip "Open this capture’s page in the Cortex Cloud tab") in place of such a description: `nanoShell.openCloudCapture(id)` → IPC `open-cloud-capture` in `src/main.js`, which accepts only a UUID and loads `CLOUD_URL + 'neural-capture/view/' + id` in the Cloud tab and shows it; no shell (web preview) → no button; nothing is sent to the pedal. Loaded by the page before `transfer.js` and required by `src/main.js`, like `links.js`.
- `pro/transfer.js`: streamed transfers to the pedal, one at a time: capture upload (type 13, `docs/INVESTIGATION.md` §6), Cloud IR (15, §6a), capture audition (150) and the audition stop (148, §12). After a confirmed stop of either audition `pro/ui.js` reads the current state again (`NanoLive.readCurrentState`), as the official app does: during a capture preview the pedal's state names the previewed capture (the demo pedal models it). `src/editor-preload.js` is the only bridge into the editor page: it delivers capture and IR bundles fetched by `src/main.js` with the Cloud tab's session (`src/cloud-ir.js` checks the WAV).
- `pro/live-sync.js` (from #14): live reports from the pedal (26, 31, 64, 94, 99), the expression position and read-back, a counter of completed state reads (`NanoLive.readCurrentState()`), and the outermost `onC305` wrapper that hands every layer exact notification bytes. Core-level, loaded after core.js; `pro/ui.js` plugs in through `NanoLive.hooks`. Upstream's `editor/index.html` is never edited for this.
- `pro/ui.js` and `pro/ui.css`: the whole UI. It overrides the hooks on `window`. Demo mode (`?demo`, or no Web Bluetooth) fakes the write characteristic and answers typed requests (preset change, rename, library, slot loads, tuner) through the real parsers, so writes still go through the real packet builders.
- Preset reorder (`onPresetPointerDown` in `pro/ui.js`): pointer events, not HTML5 drag and drop, so the closed hand shows for the whole drag (an OS drag session owns the cursor); the ⋮⋮ grip on the hovered row is the hint, the whole row drags. Category colours all come from `stageColor()`; `READABLE` overrides upstream's `FX_COLORS` (lifted modulation/EQ, pink reverb) — keep the native `Theme.category` equal.
- Metronome (N): Simple / Advanced overlay. `metroBarEvents(setup, bar)` in `pro/ui.js` is the pure event generator (the spec for the native port); the scheduler consumes it, trainers apply only at bar starts, sounds go through `soundFor(role)`.
- **Metronome sounds** (Settings → Metronome → Sounds): three sound roles, `accent`, `main` (normal and soft beats; soft is the main sound, quieter) and `sub` (count-in has no sound of its own). Each has a built-in voice (`metronome.sounds[role]`, migrated from the old single `sound`) and optionally a custom sample (`metronome.samples[role] = { name }`, the file name only). **Samples live in `app.getPath('userData')/metronome-sounds/<role>.<ext>`**, a copy made by `src/metro-samples.js` (no Electron; IPC `metro-sample` with op `pick | save | load | reset | discard` and a role, sender checked; main shows the dialog, refuses files over 5 MB, reads the bytes and copies them only after the page decoded them, so the page never names a path). The page decodes each sample once (`prepSample`: mono by averaging, not normalised, first 2 s; Chromium's `decodeAudioData` takes WAV, MP3, AAC/M4A, FLAC and Ogg Vorbis/Opus on all three platforms, but not AIFF or ALAC, so `readAiff` reads uncompressed AIFF/AIFF-C) and plays it through the same context at level × volume. A refused file shows its reason in a line under the rows (no toast; a toast only when a sample is trimmed). At launch a missing or unreadable copy falls back to the built-in voice, clears that role's setting (an unreadable copy is deleted) and shows one toast. Every click, built-in or sample, ends where the next one starts (`click()`: its own gain node fades to 0 over 5 ms, a sample's source stops there; same rule as the native edition). The UX test drives it with a temp folder and a stub dialog (`__metro.samples.setBridge`).
- Settings (⌘,): accent, metronome defaults, reconnect at launch, Developer tools, Activity at launch. Page prefs live in localStorage (`settings.*`, `metronome`); what main needs before the page loads (accent for the Dock icon, the remembered pedal, `devTools` for the menu) is in `userData/settings.json`.
- **Developer tools** (`settings.devTools`, off by default; Settings → General → Advanced): gates Record, the Activity drawer and ⌘L, "Sent: …" in the status bar, Activity at launch, Raw settings and the device/capture hashes (elements with class `dev-only`, hidden unless `body.dev-tools`), plus View → Classic Editor / Reload Current / Developer Tools (`src/menu.js`, rebuilt via `nanoShell.setDevTools`). The UX test turns it on with the real switch near the start. Not gated: the dev remote, the `[editor]` terminal mirror, demo mode.
- Activity log file for everyone: main writes every editor console line to `app.getPath('logs')/nano-cortex-editor.log` (`src/activity-log.js`: batched ~1 s, rotates to `activity.1.log` past 2 MB). Help → Show Log File reveals it. `src/accent-icon.js` renders the accent icon. `src/editor-preload.js` exposes `window.nanoShell` for these.
- `src/main.js`: the window, both tabs as `WebContentsView`s, permissions, the Cortex Cloud session partition (`persist:cortex-cloud`), and the wiring for the Bluetooth device picker (Electron has none; see `select-bluetooth-device`).
- **Auditions on quit** (`src/quit-guard.js`, no Electron, tested by the UX test with the real page and a fake app): the page reports whether anything is auditioned (`nanoShell.auditionState`, from `render()` and `notifyPreviewState`, not from the drawing, which pauses while the Cloud tab hides the page). `before-quit` and the window's `close` (closing it quits) then hold the quit, run `window.__stopAuditionsForQuit()` (148, the pedal's 149; no state read) and quit after the answer or 1.5 s, whichever is first; a second quit meanwhile is held, a page that is gone or hung never blocks. One Activity line, word for word the native edition's (`QUIT_LINES`): "Quit: stopped the preview first (the pedal confirmed in N ms).", "Quit: the pedal did not confirm stopping the preview; quitting anyway." or "Quit: the pedal did not answer the preview stop within 1.5 s; quitting anyway." The update modal's Restart goes through `beforeRestart` the same way. Demo hooks: `__demo.hooks.refuseStop`, `stopDelay`.
- **Bluetooth link release** (`pro/ui.js`, "releasing the Bluetooth link"): whenever the page decides it is disconnected (`setStatus('Disconnected')`: gattserverdisconnected, a write that failed because the link is gone, Disconnect, a connect that failed half-way) it calls `gatt.disconnect()` on the device it had and drops `state.device` / `server` / `c304` / `c305`; a device that still reports a connection stays in `__ble.devices`, and before every `requestDevice()` (wrapped always, not only in the shell) any such object is disconnected. `powerMonitor` in main: `suspend` → `window.__systemSuspend()` (clean disconnect, logged); `resume` → after 3 s `window.__systemResume({ pedal })` with a user gesture, which reconnects like the launch reconnect (an `auto` scan) whenever it was connected before the sleep and a pedal is remembered. Not tied to "Reconnect to the last pedal at launch" (launch-only): the native edition reconnects after any dropped link, wake included (this edition has no reconnect after a plain drop). The UX test covers it with fake device objects (`__ble.requestDevice`).
- **Bluetooth picker** (`src/bt-picker.js`, no Electron, tested by the UX test with fake devices; issue #15): right before each `requestDevice()` the page sends `bt-request` (sync, via `nanoShell.bluetoothRequest`) and gets the scan mode: `nano` (requestDevice filtered on A002/A003, the default) or `all` (every device; the chooser's "Show all Bluetooth devices", and the default once a pedal was found that way: `pedal.via`). The remembered pedal, or in a `nano` scan the first device, or in an `all` scan a name like "Neural DSP Nano Cortex", is taken at once; otherwise the page draws the chooser (`bt-chooser` → `showBleChooser` in `pro/ui.js`, every device, sorted, live; Scan again = cancel + new request). `userData/settings.json` `pedal` is written only when the page reports `bt-result 'ok'` (C304/C305 found, from `setStatus(…, true)`); `'no-service'` (both services answered "No Services matching") marks the device not-a-Nano for the session, forgets it if remembered and reopens the chooser through `window.__connectAgain` with a user gesture. A dropped link during discovery is `'failed'` and forgets nothing. The Classic Editor has no chooser, so main shows a native list for it.
- `test/ux-test.js`: drives the UI with real mouse, wheel and key events. It asserts both UI state **and the exact packets sent**. Its check names are effectively the behaviour spec.
- Dev remote for hardware sessions: `NANO_DEV_PORT=4848 npm start`, then `curl -d '<js>' http://127.0.0.1:4848/eval` runs JS in the editor page (`?target=cloud` for the Cloud tab), `/log?since=N` returns the Activity log, `/shot?target=cloud&file=…` screenshots (never put Cloud-tab screenshots in the docs). Localhost only, never in packaged builds. **Browser requests are refused** (`src/dev-remote.js`, `devRemoteRequestAllowed`): any request with an `Origin` or `Sec-Fetch-Site` / `-Mode` / `-Dest` header, or a `Host` other than `127.0.0.1:<port>` / `localhost:<port>`, gets a 403 `{"ok":false,"error":"browser requests are refused"}` before anything runs (a web page can make a browser call a localhost port, `text/plain` POST to `/eval` included; curl and scripts send none of these). **`/shot` writes only a `.png`** inside `test-output/`, `docs/images/`, the OS temp folder or `/tmp` (relative paths start at the repo root, symlinks are followed first), else 400; without `file` it writes `nano-shot.png` in the temp folder.
- Session recording: **Record** in the status bar captures every TX/RX packet with timestamps plus the log, and saves JSON (from source: `test/fixtures/sessions/`, git-ignored; never commit recordings). When run with `npm start`, the editor's Activity log is also mirrored to the terminal as `[editor] …`.

## Platform notes

- **Shortcut labels**: write them the Mac way (⌘S, ⇧⌘S, ⌥⌘I) and pass them through `keyLabel()` in `pro/ui.js`; off-Mac it shows Ctrl+S, Ctrl+Shift+S, Ctrl+Alt+I. Static `title`s and `<kbd>`s in `pro/index.html` are converted at boot. The platform comes from `nanoShell.platform` (preload); `?platform=mac|win|linux` overrides the labels only (the UX test uses it). Key handlers use `modKey(e)` (⌘ on macOS, Ctrl elsewhere) from the real platform. Menus use `CmdOrCtrl`.
- **macOS only**: Dock icon (`app.dock`), `hiddenInset` title bar, the app menu (Settings… is under Edit on Windows and Linux; `menu.js` treats anything non-mac the same). Windows and Linux set the window icon (`BaseWindow` `icon`, then `win.setIcon` for the accent icon).
- **Linux**: AppImage + deb for x64 and arm64 (`build.linux` in `package.json`, artifact names `…-linux-x86_64.AppImage`, `…-linux-arm64.AppImage`, `…_amd64.deb`, `…_arm64.deb`). Web Bluetooth needs `enable-experimental-web-platform-features` (set in `main.js`) and BlueZ. Log file: `~/.config/Nano Cortex Editor/logs/nano-cortex-editor.log`. Not hardware-tested yet; fix Bluetooth issues as they are reported.
- **macOS signing**: releases are signed with "Developer ID Application: Anup Sebastian (272K9YT73Z)", hardened runtime on, notarised and stapled. `release.yml` (macOS job only) uses the repo secret `OP_SERVICE_ACCOUNT_TOKEN`, a 1Password service account that can read only the vault **Apple Signing**: item **Apple Developer ID** (document `developer-id-application.p12`, fields `password`, `team id`) and item **App Store Connect API Key** (document `AuthKey_<id>.p8`, fields `key id`, `issuer id`). It fetches them into `$RUNNER_TEMP/apple-signing` with `op document get` / `op read`, masks them, imports the .p12 (plus Apple's Developer ID intermediates) into its own temporary keychain on the search list (not `CSC_LINK`: electron-builder 26.15's import passes the .p12 password to `set-key-partition-list` as the keychain password and fails), exports `APPLE_API_KEY`, `APPLE_API_KEY_ID`, `APPLE_API_ISSUER`, `APPLE_TEAM_ID`, and overrides the config on the command line (`-c.mac.identity="Anup Sebastian (<team>)" -c.mac.hardenedRuntime=true -c.mac.notarize=true -c.dmg.sign=true`); electron-builder notarises and staples the .app before zipping, then the job notarises and staples each dmg with `notarytool` and deletes the keychain and files in an `always()` step. `package.json` keeps the defaults for everyone else: `mac.identity` `"-"` (ad hoc, `hardenedRuntime` off, `notarize` false), so local `npm run dist` and fork dry runs still build (without any signature a quarantined copy is reported as "damaged" on Apple Silicon). A tag push or a `release_tag` run without the secret fails rather than ship an ad-hoc build. Entitlements (`build/entitlements.mac.plist`, same in `.inherit.plist` for the helpers): `cs.allow-jit` (V8) and `device.audio-input` (the metronome's output list needs microphone access); Bluetooth needs only the Info.plist strings in `extendInfo`. The job checks the app inside each zip and dmg: `codesign --verify --deep --strict`, the Developer ID authority, `spctl -a -vv -t execute` → `source=Notarized Developer ID`, `xcrun stapler validate`. Windows and Linux are unsigned and never see the Apple secrets.
- **Updates** (electron-updater, a runtime dependency; `src/updates.js`, no Electron, tested by the UX test with a fake updater): packaged builds only (`startUpdates()` in `main.js` returns when `!app.isPackaged`, so never from source or in the UX test). Checks 10 s after launch and every 24 h while `settings.json` `autoUpdate` is on (Settings → General → Advanced), and on Help → Check for Updates…; `autoDownload` off, `autoInstallOnAppQuit` on (only ever installs what the user chose to download). Events go to the editor page (`update-event` → `updateEvent` in `pro/ui.js`, the modal; `__updates.event` in tests); answers come back as `update-action` (`download` | `skip` → `settings.json` `skippedVersion`, ignored by automatic checks but offered on a manual one | `later` | `restart` → `quitAndInstall(false, true)`). Install mode from `installMode()`: macOS zip (Squirrel.Mac; needs the Developer ID signature, ad-hoc builds are refused at install), NSIS, AppImage (`APPIMAGE`); notify-only (Download opens `releases/tag/v<version>`): portable exe (`PORTABLE_EXECUTABLE_FILE`) and deb (electron-updater picks its DebUpdater from `resources/package-type`, but the app never downloads with it). On macOS `update-downloaded` comes before Squirrel.Mac validates the signature, so an error after it means "couldn't be installed". **Release metadata**: `package.json` `build.publish` is GitHub (`AJs-Creations/nano-cortex-editor`), but electron-builder never publishes (`--publish never`); every build writes `latest-mac.yml` (both mac zips; `dmg.writeUpdateInfo` false, since the dmgs are stapled after hashing), `latest.yml` (the NSIS installer; the portable exe writes none), `latest-linux.yml` / `latest-linux-arm64.yml` (the AppImages, blockmap embedded, plus the debs), and `.blockmap` files for the zips and the NSIS exe. `release.yml` uploads them with the installers, metadata last, in both the tag and the `release_tag` paths. A release without them breaks updates for that platform (automatic checks stay quiet; Check for Updates… shows the error). Releases must not be drafts or prereleases to be seen.
- **Adding files to an existing release** (no new version): `gh workflow run release.yml --ref main -f release_tag=v1.0.0 -f platforms=mac,linux` (`platforms`: `all`, `mac`, `linux`, `mac,linux`). Without `release_tag` the dispatch is a dry run (workflow artifacts only).

## Protocol essentials

- BLE GATT: services `A002`/`A003`, write characteristic `C304`, notify characteristic `C305`. Typed frames are `[len = frame.length − 2] C0 [protobuf payload] [u32 LE message type]`; `MSG` in core.js names the known types. Older-style frames (state requests, FX/amp writes) have other trailing bytes.
- **Preset switching** is over GATT (`SetPresetSlotsRequest`, type 29, acked with type 30), verified on hardware. No MIDI port is needed.
- **USB is one-way:** the pedal accepts MIDI PC 0–63 and CC 34–43 over USB but sends nothing back. There is no USB editing protocol; Cortex Control does not support the Nano.
- The pedal accepts **one BLE connection**. The Cortex Cloud phone app has to be disconnected.
- Upstream tested against firmware 2.2.1. The editor's tested firmware is `COMPAT.testedFirmware` at the top of `pro/ui.js` (the native edition has its own constant). A pedal reporting a newer version (numeric per component, suffixes like `+06d34443` ignored) gets a one-time banner under the header (`#fwNotice`, remembered per version in `settings.firmwareWarned`).
- **Unknown effects**: a slot whose model id isn't in upstream's tables stays `'None'` inside the core (so core.js never writes or refreshes its parameters) and carries `block.unknownId`; the UI shows "Unknown effect" / "Newer firmware?" and only allows on/off and picking a known effect. `setFXParam` and `requestNextFXParamRefresh` are wrapped to refuse it as well. Demo hooks: `?demo&demoFirmware=2.3.0&demoUnknown=post2:7E`.
- **After a firmware update**: (1) read Neural DSP's release notes for new or changed effects; (2) trace each new effect in the official app (Record / HCI trace: model id from the state dump fields 48–52, parameter order and ranges from the param writes); (3) add them to the model tables (upstream's, or an override layer in `pro/ui.js` if upstream hasn't caught up; never hand-edit `pro/core.js`), test on the pedal, then raise `COMPAT.testedFirmware` and the native edition's constant together.

## Working rules

- **Backlog**: the shared soft idea list for both editors is `../nano-cortex-editor-mac/BACKLOG.md` (`BACKLOG.md` here points at it). Not a plan; ask at task boundaries whether Anup wants to pick from it.

- **Feature parity with the native app** (`../nano-cortex-editor-mac`): every feature Anup asks for lands in both editors unless it genuinely cannot apply to one; he is still deciding between them. This app's CSS is the visual reference for the native one.

- **One version for both editions, always current.** This edition and the native one release together under the same version (1.2.0 was the first shared one). Settings → About shows it, so bump it in both repos in the same round, before tagging: here `package.json` (and `package-lock.json`) plus `pro/links.js` (the UX test checks they match), there `MARKETING_VERSION` in `project.yml`. `release.yml` refuses a tag that differs from `package.json`.

- **Hardware in the loop.** Anup has the pedal. For anything protocol-related, ask him to do the physical step and read the Activity log (⌘L, Developer tools on), rather than guessing byte formats.
- Before the first write to a real pedal, make sure his presets are backed up in the official app.
- Edits are live on the pedal; **Save** (⌘S) commits them to the preset. Never save without an explicit user action.
- Never send MIDI to a port that isn't the Nano.
- Keep demo mode working, and keep `npm run test:ux` green. Add checks for new behaviour.
- If the UX test fails on the Mac, fix the harness before suspecting the app, and confirm by hand.
